\section{Sequence diagram}
\label{sec:sequence}

\subsection{Đăng nhập}
\begin{figure}[H]
  \centering
  \includegraphics[width=\linewidth,height=0.8\textheight,keepaspectratio]{img/seq-login.png}
  \caption{Đăng nhập: handshake TCP rồi mở kênh UDP}
  \label{fig:seq-login}
\end{figure}

Trong quy trình đăng nhập (\cref{fig:seq-login}), hàm \fname{Mux.Accept} được gọi ngay ở bước xử lý \texttt{AUTH}
trên TCP để tạo sẵn đối tượng \fname{Conn} trước khi gói PING đầu tiên của client tới cổng 9001. Danh sách user
trả về trong \texttt{AUTH\_OK} giúp client khởi tạo danh sách ban đầu ngay sau khi đăng nhập; các thay đổi trạng
thái online về sau được đồng bộ qua kênh UDP bằng bản tin \texttt{users} phát cho cả phòng.

Đăng ký (tab Đăng ký trên Web UI, \texttt{/register} trong CLI hoặc cờ \texttt{-register}) dùng cùng sơ đồ, chỉ
đổi message thứ ba thành \texttt{REGISTER}: trước khi gọi \fname{AddPending}, server kiểm tra luật tên và mật khẩu,
từ chối tên đã tồn tại, tạo tài khoản với salt mới và ghi xuống \texttt{users.json} (\cref{subsec:handshake}).

\subsection{Một tin nhắn riêng}
\begin{figure}[H]
  \centering
  \includegraphics[width=\linewidth,height=0.8\textheight,keepaspectratio]{img/seq-dm.png}
  \caption{Vòng đời một tin nhắn riêng từ trình duyệt người gửi tới trình duyệt người nhận}
  \label{fig:seq-dm}
\end{figure}

Khi gửi tin nhắn (\cref{fig:seq-dm}), server không gửi vòng bản tin đó về lại cho người gửi mà JavaScript trên
trình duyệt tự hiển thị ngay khi nhận \texttt{200 OK} từ \texttt{POST /api/send}. Với tin nhắn broadcast, luồng đi tương tự nhưng server đẩy bản tin vào hàng đợi \texttt{sendCh} của mọi session đang active
(trừ người gửi).

\subsection{Gửi file qua server}
\begin{figure}[H]
  \centering
  \includegraphics[width=\linewidth,height=0.8\textheight,keepaspectratio]{img/seq-file.png}
  \caption{Gửi file qua server theo kiểu pipeline, kiểm tra SHA-256 đầu cuối}
  \label{fig:seq-file}
\end{figure}

Khi truyền file (\cref{fig:seq-file}), vì phần metadata nằm ngay ở đầu stream (\cref{subsec:app}), server tách xong
metadata là tạo ngay một goroutine \fname{relayFile} đọc từng mảnh byte từ channel đệm (tối đa 256 mảnh) và ghi
tiếp sang stream phía người nhận theo kiểu pipeline. Nếu người nhận mất kết nối giữa chừng, stream gửi
xuống trả về lỗi, server ghi log và xóa bỏ các mảnh còn lại để không chặn luồng đọc của người gửi. Khi gửi file cho
cả phòng (trường \texttt{to} để trống), server mở đồng thời một stream tới từng client đang online và fan-out từng
mảnh dữ liệu sang tất cả các stream đó.
